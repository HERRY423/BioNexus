当前只能回答“已有局部机制证据，真实联合效果尚不确定”。本轮读取的历史文件显示：

- 9 月 15 日修复快照：合法保留 12/12，无效放行 0/42，机制预期匹配 54/54。
- 54 例来自 18 个开发者标注家族的相关改写，独立研究数为 0。
- 外部先导记录：真实任务、站点、双合格盲评和完整成本记录均为 0；本轮读取的 IVN 实验室研究、非作者评审、校准冻结列表仍为空。

这些是既有工件的读取结果，不是本轮重新运行候选引擎的成绩。54 例已经用于开发，不再允许进入验证留出集。它们证明过度拦截可以在工程上修复，不证明未知任务表现、模型增益或人工节省。

## 两个需要分开的试验

**主试验：固定候选声明的判定。** 每个任务包含一个精确命题、使用范围、结果、设计和执行记录，两组判定同一个命题。这样能控制分母，并分辨错误接受与合法结论误拒。本次评分器实现这一试验。每个命题的物种、群体、条件、比较方向、效应方向、不确定性及推断层级都必须固定。复合句先拆成原子命题。

**后续试验：开放生成的发现保留。** 让两组从相同结果提出结论；独立专家将生成文本拆成命题、匹配去重，并审阅新增命题。预先冻结的参考发现集合提供召回分母，新增合法发现单独报告。未提及的合法发现、空白输出、只说“需要更多研究”和技术失败都不能被算作安全且有用。固定命题的 ACCEPT 率不能替代开放发现召回率。本评分器不冒充已实现这一后续研究。

## 对照与干预

| 组别 | 获得的信息和资源 | 唯一预定差异 |
|---|---|---|
| baseline | 相同任务包、原始执行证据、工具及规则说明、相同输出字段 | 允许按通常方式审阅；不强制逐声明验证绑定 |
| assisted | 与 baseline 相同 | 要求逐声明验证数据/结果/设计/执行记录的对应关系，并报告绑定失败或证据范围不足 |

baseline 应是有能力的常规工作流。不能用 accept-all、弱提示、较差模型或不给证据的流程充当主对照。两组均可查验完整文件。绑定核验模块是干预本身；所有基础分析工具、通用证据访问、解释规则及预算保持一致。差异提示只规定绑定行为；附加长篇科学教程、更多证据或额外推理预算将混入其他干预。

主试验重放同一份已经完成的执行证据，不让两组重跑出不同分析再比较结论。两组采用新的隔离会话，禁止记忆、共享历史及先看另一组答案。冻结模型的实际快照标识、宿主版本、系统/公共提示、工具清单及版本、容器/环境、温度及可用 seed、工具调用和 token/时间上限。seed 可用时采用预定配对序列；相同 seed 不证明输出可重复。重复运行按任务内重复处理，不增加独立研究数。

如果无法固定服务端模型快照，记录供应商返回身份与运行批次，交错运行两组；这批数据只作探索观察。实际宿主 trace、运行请求、返回模型标识、用量和所有工具调用应由保管者核对。本地字符串相同不足以证明真实宿主相同。

可选机制消融单独预注册：相同规则清单但无绑定、仅文件完整性绑定、文件绑定加语义/设计检查。主分析先固定 baseline 对 assisted；不能看结果后挑最弱对照。错配收据是标记清楚的受控反例，不能混成真实自然任务。accept-all/reject-all 仅用作评分器退化策略控制。

## 任务、参考判断与人工分配

1. 先由未参与开发的保管者选取真实已完成的多供体单细胞 DE 任务，登记全部纳入项及排除原因。第一阶段限定这一范围，避免把不同科学任务混为一类性能。
2. 纳入有支持的阳性、有边界的非显著结论、合法限制性结论，以及方向/统计单位/设计/多重比较/因果层级/文件版本不匹配等任务。自然任务与构造反例分开报告；构造反例用 `SYNTHETIC_DEMO`，不进入真实留出效果。
3. 每个原研究只有一个 `study_cluster_id`；同数据、同供体来源的派生任务和改写属于同簇。软件拒绝把同一个数据摘要拆为不同簇，但不同摘要是否来自同源研究仍需保管者审阅。
4. 两位独立领域专家在任何组开始前冻结参考标签、依据和允许的结论范围；不得接触分组输出，不得参与开发或对应任务的执行。`VALID` 指精确命题在指定用途内获得支持；不显著不等于等效或无生物作用。`INVALID`、缺证据和争议原因分开记录；缺乏共识保留 `UNRESOLVED`，不能由 BioNexus 自己生成真值。
5. 人工复核采用任务内配对、不同研究者分别审阅两组。每位研究者只看同一案例的一组；在不同案例间平衡其组别和任务顺序。由保管者用预先保存的随机序列按经验/机构分层分配，保存分配文件；不能让熟练者全去 assisted。当前工具检查已冻结的操作者及重复接触，不声称认证随机过程。
6. 界面和文件名去除组别/品牌提示；绑定结构本身可能暴露组别，因此记录复核者猜测及把握度。将“对研究假设/品牌盲法”与“无法完全遮蔽的结构差异”分别报告。参考专家始终对组输出盲法。
7. 记录模型初始判定、研究者最终判定、修改理由、找到的具体证据位置、争议及失败。评分器的 `decision` 是最终人工辅助流程对原命题的决定，输出工件同时保留模型初始决定；不能把改写成另一个更弱命题算作保留原命题。修复后的合法结论另作次要结果并计入修复成本。
8. 招募前由实际机构判断隐私、参与者同意和伦理要求。本轮不生成研究者姓名、签名、批准或模拟人工用时充当研究记录。

## 终点、分母与失败标准

设 U 为 INVALID 原命题被 ACCEPT 的比例，R 为 VALID 原命题被 ACCEPT 的比例，T 为全部入组任务平均完整人工人分钟。报告 ΔU = U_baseline − U_assisted、ΔR = R_assisted − R_baseline、ΔT = T_baseline − T_assisted。

所有阈值必须在解盲前由研究负责人确定并冻结，模板故意不填写“漂亮”的默认值：

| 字段 | 含义 | 描述性门槛 |
|---|---|---|
| minimum_unsupported_reduction | 最小有意义的无依据接受率降低，绝对比例 | ΔU 严格大于此值 |
| maximum_valid_retention_loss | 可接受的合法保留绝对比例损失 | ΔR 不低于该值的负数 |
| minimum_valid_retention | assisted 的绝对合法保留底线，必须大于 0 | R_assisted 不低于此值 |
| minimum_minutes_saved_per_task | 每任务最低有意义的完整人工节省 | ΔT 严格大于此值 |

四项共同成立才能记录 `joint_sample_criteria_met=true`。保留底线防止两组都把合法发现大量扔掉仍宣称“非劣”。baseline 已保留全部合法结论时，无需再严格减少零误拒，只需达到预先指定的保留标准。旧评分器“双错误都严格减少”的指标仍原样保留，不能把两个不同问题混写。

FAILED 对合法命题算未保留；缺失输出留在登记分母，原评分器另列最坏情形错误率。缺参考、争议、成本缺失、条件失配或原始工件未核查都会使联合样本门返回 null。描述性差值可继续显示，但不能选择完整且好看的子集冒充整个队列。将阴性、恶化、不确定三个结果分别报告；成本下降但质量恶化不能作为成功。

单纯 INVALID 分母上的 U 不代表最终报告中无依据命题占比；另报接受总数、接受结果中的无依据比例、任务完成率、解释定位准确性和逐家族保留率。不能用“找到任一严重问题”代替命中了该例真正错误机制。

## 统计分析与样本量冻结

本工具输出任务加权的配对描述性差值、原研究簇分层及完整缺失记录，不输出显著性、非劣效证明或自动认证。`analysis_plan_sha256` 所绑定的正式统计方案应在首个输出前保存于外部保管者处。

先导研究只估计任务难度、两组不一致比例、研究内相关性、研究者差异、计时方差和失访率；先导任务不能回流为验证留出任务。正式样本量用这些估计做模拟功效分析，以三个主要终点联合达到预定功效为目标，而非按基因/句子数量凑样本。没有这些信息时，不给出虚构的“足够 N”。

正式主分析预定：保留任务配对，针对 U/R 使用适合二元结果的边际模型，针对 T 使用允许偏态的均值差分析；考虑原研究簇及复核者跨任务造成的相关性。保管者与统计人员在分析方案中选定交叉随机效应模型或相应多维聚类重抽样，并用模拟覆盖率核查所选方法。不能仅按单个声明作独立 Bernoulli 检验，不能只按研究簇 bootstrap 却忽略复核者交叉效应。

联合结论要求预注册置信界同时支持 U 的优效、R 的非劣及绝对保留底线、T 的优效。预定单侧错误率、同时结论规则、缺失敏感性、失败处理、权重及停止规则；主要联合假设和消融/子组探索分别处理。样本不足、区间宽或交叉模型不收敛时报告不确定，禁止用显著性不成立来证明非劣。报告任务加权和研究等权的敏感性分析，防止大研究主导平均结果。

评估工具的 `joint_sample_criteria_met` 只是点估计阈值检查，即使为 true，`inferential_support=NOT_ASSESSED`、`causal_benefit=NOT_ESTABLISHED` 仍不改变。正式统计分析及独立身份/执行核验是后续研究工作，工具不会把它们伪装成已完成。

## 真实人工成本采集

五类互斥成本为 installation（含输入整理和接入）、review、false_alarm_handling、repair、communication。每位参与者各自记录活动区间；两人各工作十分钟为二十人分钟。同一人任何任务/组别间的时间重叠会被拒绝；暂停、休息和机器无人运行时间不计人分钟。机器时长、token、费用另表保存。

每个计时事件包含 `event_id, case_id, arm, category, person_id, source=HUMAN_ACTIVE_TIMER, started_at, ended_at, raw_log_sha256`，时间带时区。`time_logs_complete[arm]=true` 由保管者核对后填写；未知成本保持 null，真实零成本明确填 0。逐事件总数必须与五类任务成本一致。成本包括被拦截后的解释、假警报消除、修复及共同作者沟通，直至最终复核关闭；`finished_at` 是这一阶段结束时间，不只是模型返回时间。

共享安装事件在原始总日志中分为互不重叠的分摊区间绑定各任务；同一时段不能复制到多个案例。两组分摊总和分别与 `installation_totals[site_id]` 核对，不能摊给未来假想任务。报告一次性投入及本次队列摊销结果。若要区分研究测量自身的开销，两组采用同一方式并另列；普通科研使用必需的成本不得移出总账。

## 可执行入口与数据合同

在已安装当前源码的环境中运行；直接从本工作区运行时先设置 `$env:PYTHONPATH = (Join-Path (Get-Location) 'src')`。这是离线记录评估，不调用模型、外发数据或生成专家意见。

```powershell
python -m bionexus.matched_claim_study template --out matched-plan.json
# 负责人填写并冻结计划后，生成空白观察表：
python -m bionexus.matched_claim_study template --plan matched-plan.json --out matched-observations.json
# 收集真实记录后评分；digest 必须来自保管者预先独立保留的规范 JSON 摘要：
python -m bionexus.matched_claim_study score matched-plan.json matched-observations.json --evidence-root evidence --expected-plan-sha256 <digest> --out matched-summary.json
```

计划和观察表沿用 [原评估合同](external-gain-and-correctable-governance.zh-CN.md)，增加以下字段：

| 位置 | 新字段 |
|---|---|
| plan.matched_protocol | schema、shared_conditions、arm_prompt_sha256、allocation_sha256、analysis_plan_sha256、endpoints |
| 每个计划案例 | study_cluster_id、execution_evidence_sha256、operators.baseline/assisted |
| 每个组输出 | conditions（全部公共条件）、execution_evidence_sha256、prompt_sha256、binding_enabled、session_id、fresh_session、started_at、trace_sha256；两组均需 source_sha256 |
| 每个观察案例 | time_logs_complete.baseline/assisted |
| 观察表顶层 | time_events、artifacts（文件 SHA-256 到证据目录下相对文件路径的映射） |

`shared_conditions` 的精确字段见模板：model_snapshot、host_version、tools_sha256、environment_sha256、generation_config_sha256、common_prompt_sha256、resource_budget_sha256。哈希字段指对应文件的原始字节摘要，`source_sha256` 指冻结源码归档文件；计划摘要单独使用 `de_external_study.digest` 的规范 JSON 算法。不要把源码树摘要、归档摘要和原始文件摘要混用。

`artifacts` 保存冻结源码归档、任务/数据/执行证据、配置/提示、分配与分析方案、参考判断、输出、trace 和原始计时文件。路径只能在 evidence-root 内，逐文件流式重算 SHA-256；缺失列为 blocker，内容不同直接报错。原始计时文件使用单个事件 JSON（不含自身 raw_log_sha256），必须与 time_events 中对应事件一致。文件字节匹配证明保存了这些文件，仍不证明文件中声称的执行或人类活动真实发生。

两组实际输出、失败和初始/最终决定保存在 artifact 文件里。保管者核查 trace 中的模型、输入、调用、预算及最终文本与观察表一致，并检查两份 arm prompt 差异是否仅为预定干预。评分器没有通用模型日志解析器，不会声称完成该人工真实性核查。

工具拒绝覆盖旧输出。修改模型、输入、规则、主终点、分配或参考范围时保存新计划及继承关系，不能改完旧文件继续使用旧摘要。探索中发现的规则问题进入纠错记录，确认性留出结果保持原样。
