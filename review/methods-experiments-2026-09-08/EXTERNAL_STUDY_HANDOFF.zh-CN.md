# 外部验证交接：可执行，尚未发生

当前外部专家评分数、参与实验室数、真实模型调用数和人类审阅时间记录数均为 **0**。本文件及空表是准备工作，不是实验完成证明。当前受测版本尚不满足开展产品优越性确认试验的条件：原始审计有效陈述保留率为 0/12；仅放宽极小 P 值启发式后，24/42 个错误案例被放行。

## 1. 独立专家标注

`reviewer-packet.zip` 包含 54 个随机编号案例、原始输入/结果/设计矩阵/执行记录及空白评分表。给评审者分发此压缩包，不要给 `reviewer-key-PRIVATE.csv`、产品判定、消融输出或研究结果。两个评审者分别填写，各自完成前不交换答案；第三位负责人裁决分歧，保留最初意见。评审者身份、项目关系、专业资格需真实记录；随机编号本身不构成独立性。

评分：SUPPORTED_WITHIN_SUPPLIED_EVIDENCE / UNSUPPORTED / INSUFFICIENT_EVIDENCE / UNRESOLVED。要求具体证据位置、错误类别和理由。样本中有同一错误家族的三个相关改写，统计单位应以家族或真实独立任务聚类，不能把 54 当作 54 个独立研究。

本包是作者设计的挑战集，已经看过结果，适合诊断和评审流程试运行。**不能把其二次标注包装成未见过的确认集**。确认阶段需由外部保管者收集未参与开发的真实完成任务，按研究/实验室整体留出，并在解封前冻结版本、端点、排除规则和样本量。

## 2. 同模型的真实对照

待有实际 API 凭据和固定模型版本后，使用相同分析结果、模型快照、工具输出、温度、token 上限和输入权限。四臂为 A 原始宿主、B 宿主加科学清单、C 宿主加独立 LLM 复核、D 宿主加 BioNexus。复核器的模型、提示词及是否与生成器同模型必须记录。记录请求、完整回答、延迟、输入输出 token、重试和失败。原有 `evals/host_eval.py` 可提供供应商适配入口，但其默认旧模型名与离线回放不能充当本实验的已执行模型配置。

先做相同冻结输出的事后审计比较以隔离审计贡献，再独立做允许宿主修复/重分析的前瞻任务比较；后者同时计入修复失败、额外计算、工具调用成本和最终任务完成率。不得把两个估计量混合。所有臂都需要最终输出中逐条可核查陈述和未解决问题，禁止仅靠减少输出、全拒绝或删除难题获得低错误率。

主要判据必须联合满足：错误陈述风险降低，以及有效陈述保留率达到事先确定的非劣界值。报告每任务错误数、任务完成、弃答、误拦、遗漏、科学负责人裁决及花费。作者挑战集观察率不可直接用于外部人群功效估计。建议先由外部试点估计配对不一致率和任务内相关性，再据此确定确认阶段样本量；不能先指定一个好看的任务数。

## 3. 实验室净收益

使用 `lab-time-records-BLANK.csv`，记录真实的安装/设置分摊、审阅、修复、沟通与失败处理时间。同一分析员不应先手工再看 BioNexus 重做相同任务以免记忆偏倚；采用跨任务、平衡顺序的交叉分配，不同分析员处理同一任务的不同臂。任务最终质量由不知道处理臂的负责人评定。

净时间收益 = 常规流程总耗时 - BioNexus 流程总耗时。安装、修复和误拦处理计入后者；未完成任务保留并单列，不能仅在成功任务中算节省。机器审计耗时约毫秒不等于人类省时。分实验室/研究聚类报告区间，先证明结论质量不降低，再谈净收益。

## 投稿前的具体技术门槛

1. 执行记录必须核验结果、原始 counts、样本表、实际设计矩阵的哈希、样本对齐、矩阵秩和拟合状态；自报字段不能产生“已验证”。哈希自洽也不证明外部生产者身份。
2. 科学陈述应解析为“基因、比较方向、效应符号、阈值、限定范围、否定作用域”等可核查对象；逐条与实际结果对照。未能解析时返回未评估，不得因存在结果表或出现否定词而自动认可。
3. 生物学上合法的 donor-level 强信号不得仅因 P 值很小被拒绝；先解决证据核验，再降低启发式严重级别。保留清单遗漏率与有效结果误拦率。
4. 配对设计必须显式进入实际模型矩阵；新增测试需涵盖配对、非配对和不可辨识设计。更多显著基因不能单独证明更准确。
5. 修复后冻结新版本，首先回归本轮公开的失败案例，再由外部保管者解封未见数据。回归通过是工程改善，不是新的独立科学验证。
