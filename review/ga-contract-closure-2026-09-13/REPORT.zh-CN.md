## 1. 历史报告与新执行分开

旧同步器会在未执行分析时更换报告的来源元数据。本轮撤销这一行为：`sync_flagship_reports.py` 现在只读核验，旧改写接口直接拒绝。单独输出核验结果时要求新文件，不能覆盖原报告。

十一份原有报告按原始字节封存到 [历史目录](../../validation/history/pre-ga-provenance-01/manifest.json)，原路径的报告也保持原样。清单核验确认十一份报告与封存字节相同。这证明保留完整性；因为旧同步器曾允许改写身份，不能据此恢复其原始执行真实性。

实际验证入口现在为每次尝试生成新的 `validation/runs/<run-id>/` 目录，保存执行前后文件、SHA-256 清单、源码快照、时间、退出状态、异常、变化与删除路径。失败和部分输出保留；未变化文件不会算作本次新结果。互斥锁阻止多个入口混记输出；异常退出后的残留锁需要核实进程已停止并保留失败记录后处理，不会自动清除。

当前严格核验器必须找到与当前源码及报告字节匹配的成功执行回执。只更换时间戳、版本或源码哈希，失败执行、执行中源码变化、携带未变旧报告，都不能补足当前证据。

这些回执仍是本地进程记录，不具备外部不可变存储或真实生产者认证的含义。参考 [机制与恢复说明](../../docs/validation-history.md)。

## 2. 支持与版本合同统一

机器可读权威范围为 [core-support.v1.json](../../src/bionexus/data/core-support.v1.json)，验收标准为 [GA_CRITERIA.md](../../GA_CRITERIA.md)。MAINTENANCE、版本策略、弃用政策、产品矩阵与兼容说明均指向同一范围。

| 项目 | 本轮冻结的合同 |
|---|---|
| CLI | `audit-de`、`audit-de-verify`、`audit-de-summary`，保留既有参数与退出码合同 |
| Python | 清单枚举的 DE 审阅、bundle 验证、WarrantAssessment、PolicyDecision、EvidenceCard 五个入口 |
| 数据合同 | DE bundle v1 与 integrity v1；旧数据读取兼容与新科学判断分开 |
| 科学用途 | 对已完成的多供体 DE 材料做被动审阅；明确的单基因断言和可分别核验的子句；无法唯一绑定的复合断言需要复核 |
| 独立成熟度 | annotation、spatial、模型后端、分析执行、认证、真实 host conformance 保留独立证据状态 |
| 支持期限 | 从首次 Core 1.0 GA 起十二个日历月；后续 1.x 小版本和补丁不会重启计时 |
| 旧 minor | 后继 minor 发布后九十天内回补严重安全与科学错误放行修复，且不超过已公布的 1.x EOL |
| 弃用与 EOL | 至少九十天 EOL 通知；API 移除要求至少两个 minor 和六个月弃用通知，并按 major/新合同迁移；弃用通知不自动延长回补期限 |

新增发布门禁校验支持范围、首次 GA 版本与日期、具名接受记录、联系渠道、限制和哈希绑定的核验材料。它只能校验记录结构与完整性，不能替任何人接受责任或认证身份。[GA_ACTIVATION.json](../../release/GA_ACTIVATION.json) 仍为 PROPOSED；缺少真实维护承诺时，正式 GA 检查返回 BLOCKED。

## 3. 已记录严重语义失败的关闭

| 失败路径 | 修复后的行为 | 回归证据 |
|---|---|---|
| 定向 warrant 计算异常后继续通过 | 增加必需的 PARSE_FAILED 检查，不能通过 | `test_warrant_failure_is_explicit_and_fail_closed` |
| 第一子句正确，第二子句错误或基因不存在 | 分别审查完整子句；全部结果参与总判定 | `test_false_second_or_ambiguous_assertion_cannot_pass` |
| 否定方向、同一句内矛盾断言、未解析第二个主体 | 返回缺少证据或需要复核，不借用第一个基因的检验结果 | 同上；包含本轮补充复现的六个反例 |
| 多基因或重复基因检验行被绑定到第一行 | 无法唯一绑定时拒绝通过 | `test_duplicate_gene_rows_are_ambiguous` |
| 无效、缺失、无限或零效应仍支持方向 | 上下调必须有有限、非零且方向一致的效应值；零值不改写成反方向 | `test_direction_needs_finite_nonzero_effect` |
| 供体数量被当作已控制混杂或总体代表性 | 不再据供体数虚构控制证据；明确总体外推需要另行审阅 | `test_population_transport_not_inferred_from_donor_count` |
| 一致性审阅通过被升级为总体级或真实执行认证 | 保留通过状态的既有消费接口，但结论范围限定队列内；显式声明执行未核验、生产者未认证、无科学授权 | `test_successful_consistency_audit_does_not_upgrade_evidence` |
| 旧元数据改写、失败运行、未变报告或并发输出被计入新执行 | 历史隔离、字节绑定回执、源码稳定性检查及单写入者锁共同拒绝 | `test_sync_flagship_reports.py` |

合法的单基因显著性、方向、诚实的不显著陈述和局限性陈述保留正向用例。既有负面因果/无效应、执行绑定、未知 EvidenceCard 状态与 bundle 篡改反例继续纳入门禁；未降低覆盖率阈值或通过改写旧 fixtures 制造通过。

这些回归关闭的是已记录、可复现的失败路径；不声称证明任意自然语言都能正确解析或未知缺陷不存在。

## 5. 重新审阅与尚未完成的发布验收

历史 `ROBUST_PASS` 如果涉及复合断言、方向否定、重复检验行、缺失方向效应或总体外推，应保留原报告并使用修复后的版本在新目录重审。新审阅引用旧 bundle 的位置和哈希；不能修改旧报告或把其成熟度改写为新判定。旧 bundle 能读取，不表示旧判断自动获得本轮背书。

本轮没有把历史科学报告重跑一遍。严格核验仍拒绝历史隔离报告、缺少当前执行回执，以及三条因验证入口变化而过期的 Evidence Index 源码绑定。需要真实运行相应科学验证，并在审阅其新结果后产生新的索引记录；不能只替换旧索引哈希。CI/发布工作流保留严格验证和执行记录上传，没有绕过这些失败。

独立规则审阅、真实使用验收、具名维护接受和精确候选提交上的发布验证仍是正式 GA 的后续验收项。本轮完成的是这些验收所需的工程约束与已知失败处理机制，不构成 GA 宣告。
